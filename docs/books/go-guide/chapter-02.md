# 第 2 章 基础类型和变量声明

## 本章要点

Go 在类型系统的最底层做了三项关键设计：所有未显式初始化的变量都具有确定的零值，不同数值类型的变量之间禁止隐式类型提升，而字面量与未指定类型的常量则通过“无类型常量”保留跨类型赋值的灵活性。理解这三者如何配合，才能避开整数回绕、浮点比较误差和短变量声明隐藏外层变量等常见陷阱，并在 `var`、`:=` 与 `const` 之间做出清晰取舍。

> 核对日期：2026 年 10 月 15 日；核对环境为 Go 1.27.2、Windows/AMD64。

## 2.1 零值：未初始化也有确定的值 {#ch2-1}

除另有说明外，本章正文的代码片段均位于函数体内，省略外层 `package main` 与 `import` 声明；`fmt` 对应标准库 `"fmt"`，其余标准库包在首次出现处注明导入路径。

未显式赋初值的变量，在声明后会自动获得所属类型的零值，不存在未定义内存状态：

| 类型 | 零值 |
| --- | --- |
| `bool` | `false` |
| 整数、浮点数 | `0` |
| 复数 | `0 + 0i` |
| `string` | `""` |
| 指针、切片、映射、函数、通道、接口 | `nil` |
| 数组、结构体 | 各元素或字段对应类型的零值 |

零值是语言规范给出的确定性保证。设计自定义类型时也应尽量遵循“零值可用”（Zero-Value Useful）原则，让调用方声明变量后即可直接使用，不必强依赖构造函数——例如标准库 `"bytes"` 中的 `bytes.Buffer` 和 `"sync"` 中的 `sync.Mutex`，在零值状态下就能直接读写或加锁。

```go
var count int
var ready bool
var name string
var tags []string

fmt.Println(count, ready, name == "", tags == nil)
// 0 false true true
```

需要注意，`nil` 并不是所有类型通用的“空值”，它只能表示指针、切片、映射、函数、通道和接口的零值；整型、布尔型和结构体等值类型不能与 `nil` 比较或赋值。此外，即便零值同样写成 `nil`，不同复合类型的可操作边界也不同：向零值[切片](./chapter-03#ch3-2)直接 `append` 完全合法，而向零值[映射](./chapter-03#ch3-4)写入键值则会触发运行时 `panic`。

## 2.2 字面量 {#ch2-2}

字面量（Literal）是在源码中直接书写固定值的语法形式。本节讨论的整数、浮点数、虚数、字符和字符串字面量都属于无类型常量（Untyped Constant），参与赋值或运算时才根据上下文确定具体类型；而[第 3 章的数组、切片等复合字面量](./chapter-03#ch3-1)本身就带有明确类型。

### 2.2.1 整数 {#ch2-2-1}

```go
42          // 十进制
0b101010    // 二进制（Go 1.13+）
0o755       // 八进制（Go 1.13+）
0x2a        // 十六进制
1_000_000   // 数位分隔下划线（Go 1.13+），仅提升可读性，不影响数值
```

旧式前导零写法（如 `010`）虽然仍表示八进制，但极易与十进制混淆，日常代码应统一写语义明确的 `0o` 前缀。数位分隔符 `_` 只能紧跟在进制前缀（`0b`、`0o`、`0x`）之后，或放在两个连续数码（含十六进制 `a`～`f`）之间，不能出现在字面量首尾或连续书写。由于小数点和指数符号（`e`、`p`）不是进制前缀，`1_.0`、`1._0` 和 `1e_3` 都是语法错误。

### 2.2.2 浮点数和复数 {#ch2-2-2}

```go
3.14
6.03e23
0x1.2p5       // 十六进制浮点字面量（Go 1.13+）
1.5i          // 虚数字面量
```

`0x1.2p5` 表示十六进制尾数 `1.2`（即十进制 `1.125`）乘以 2⁵，结果等于十进制 `36`；其中 `p` 表示以 2 为底的指数，且十六进制浮点字面量必须显式写出 `p` 指数部分。浮点字面量在作为无类型常量参与编译期计算时不受 `float64` 精度限制，赋予具体浮点变量时才按目标类型精度舍入。虚数字面量可与实数相加构成复数常量表达式，如 `2 + 1.5i`。

### 2.2.3 字符与字符串 {#ch2-2-3}

字符（`rune`）字面量用单引号包裹，表示单个 Unicode 码点（Code Point），默认类型为 `rune`：

```go
'A'
'中'
'\n'
'\x41'         // 按单字节十六进制指定（0x41 对应 'A'）
```

解释型字符串使用双引号，支持 `\n`、`\t` 等转义序列但不能跨行；原始字符串使用反引号，不解析转义序列且允许直接换行（内部不能包含反引号，源码中的回车符 `\r` 会在编译期自动丢弃）：

```go
interpreted := "line1\nline2"
raw := `line1
line2`
```

`string` 的零值是空字符串 `""`。它支持 `==`、`!=` 判等，支持 `<`、`<=`、`>`、`>=` 按底层字节序列做字典序比较，也支持 `+` 拼接。字符串底层是不可变的字节序列：可以给字符串变量整体赋新值，但不能按索引改写单个字节（如 `s[i] = 'a'` 无法编译）。字符串、UTF-8 编码与 `byte`、`rune` 的对应关系见 [3.3 节](./chapter-03#ch3-3)。

## 2.3 布尔与数值类型 {#ch2-3}

### 2.3.1 布尔值 {#ch2-3-1}

`bool` 只取 `true` 或 `false`，零值为 `false`。Go 不会把数值 `0`、空字符串 `""`、`nil` 指针或空容器隐式当作布尔值使用，所有条件表达式的结果都必须是 `bool` 类型。

```go
ready := true
hasItems := count > 0
canStart := ready && hasItems
shouldWait := !ready || !hasItems
```

`!` 表示逻辑非，`&&` 表示逻辑与，`||` 表示逻辑或。`&&` 和 `||` 遵循短路求值（Short-Circuit Evaluation）：只要左操作数已经足以决定整个表达式的结果，右操作数就会跳过求值。日常编码常借此把边界或空指针保护写在左侧，例如 `i >= 0 && i < len(items) && items[i] != ""`。分支与条件结构详见 [4.3 节](./chapter-04#ch4-3)。

### 2.3.2 整数 {#ch2-3-2}

Go 预声明了有符号与无符号两类定宽整数：

| 类型 | 位宽 | 取值范围 |
| --- | ---: | --- |
| `int8` | 8 | -2⁷～2⁷-1 |
| `int16` | 16 | -2¹⁵～2¹⁵-1 |
| `int32` | 32 | -2³¹～2³¹-1 |
| `int64` | 64 | -2⁶³～2⁶³-1 |
| `uint8` | 8 | 0～2⁸-1 |
| `uint16` | 16 | 0～2¹⁶-1 |
| `uint32` | 32 | 0～2³²-1 |
| `uint64` | 64 | 0～2⁶⁴-1 |

此外还有五个常用整型名称：

- `byte`：`uint8` 的类型别名（Alias），强调数据是原始字节；
- `rune`：`int32` 的类型别名，强调数据是单个 Unicode 码点；
- `int` 与 `uint`：随目标平台位宽变化（32 位或 64 位，两者位宽始终相同）；
- `uintptr`：足以容纳指针位模式的无符号整数，仅用于底层内存操作或跨语言调用，不能当作普通整数或合法指针持有对象引用。

只有网络协议、磁盘格式或二进制内存布局等对字段位宽有硬性约束的场景，才需要选用 `int32`、`uint64` 等定宽类型；常规业务计数、下标索引与长度统一优先使用 `int`。需要注意，哪怕在 64 位平台上 `int` 与 `int64` 位宽相同，它们在类型系统里依然是两种互不兼容的类型。另外，即使业务含义上“数值不可能为负”，也不宜随手选用 `uint`：无符号数做减法（如 `a - b` 且 `a < b`）或递减循环时，一旦越过 `0` 就会下溢回绕成极大的正数，造成隐蔽越界或死循环——内置函数 `len`、`cap` 返回 `int` 正是为了规避这类问题。

整数支持 `+`、`-`、`*`、`/`、`%` 算术运算、比较运算，以及 `&`（按位与）、`|`（按位或）、`^`、`&^`（位清除，将右操作数为 `1` 的对应位清零）、`<<`（左移）、`>>`（右移）等位运算。注意 `^` 作二元运算符时表示按位异或，作一元前缀（`^x`）时表示按位取反（相当于 C 系语言中的 `~x`）。所有二元算术和位运算符都支持 `+=`、`&^=` 等复合赋值形式；而 `++` 与 `--` 在 Go 中只是语句而非表达式，不能写成 `y := x++` 或 `++x`。

整数除法向零截断（如 `-7 / 3 == -2`），取余满足恒等式 `(a / b) * b + a % b == a`（因此 `-7 % 3 == -1`，余数符号与被除数一致）。除数为零常量时编译直接报错；除数为运行时零值变量时触发 `panic`。而运行时的整数加减乘溢出**不会**触发 `panic`：无符号数按模 2ⁿ 回绕，有符号数按对应位宽的二进制补码规则回绕；对溢出敏感的逻辑必须在运算前主动检查上下界。

### 2.3.3 浮点数 {#ch2-3-3}

`float32` 和 `float64` 分别实现 IEEE 754 标准的 32 位与 64 位二进制浮点数，约提供 6～7 位和 15～16 位十进制有效数字精度。除非外部数据格式硬性规定或经性能分析确认内存受限，否则应默认选用 `float64`。

二进制浮点数能精确表示 `0.5` 这类分母为 2 的幂的小数，却无法精确表示 `0.1`、`0.2` 等常见十进制小数。`==` 直接按 IEEE 754 位值规则比较，不带任何误差容忍；涉及近似计算的比较应结合数值量级采用绝对误差、相对误差或组合阈值。而金额结算等要求严格十进制精度的场景，切勿使用浮点数，应改用以最小货币单位（如“分”）计数的整型或高精度十进制库。

在官方 Go 工具链中，有限非零浮点变量除以 `0.0` 得到正负无穷（`±Inf`），`0.0` 除以 `0.0` 得到非数（`NaN`）。按照 IEEE 754 规则，任何与 `NaN` 相关的相等性比较都返回 `false`（连 `x == x` 也是 `false`），因此不能用 `==` 检测 `NaN`，必须调用标准库 `"math"` 的 `math.IsNaN`（检测无穷可用 `math.IsInf`）。另外，语言规范将“运行时浮点除零是否触发 `panic`”留给具体实现决定；但若整个除法是编译期常量表达式（如 `1.0 / 0.0`），编译器会直接拒绝，而 `x := 1.0` 之后的 `x / 0.0` 属于运行期变量求值，编译期可以通过。

### 2.3.4 复数 {#ch2-3-4}

```go
z := complex(2.5, 3.1) // 默认推导为 complex128
fmt.Println(real(z), imag(z))
```

`complex64` 由两个 `float32` 构成实部和虚部，`complex128` 则由两个 `float64` 构成。复数同样受 IEEE 754 浮点精度影响，常用数学函数位于标准库 `"math/cmplx"`。

调用内置函数 `complex` 时，两个有类型实参必须同为 `float32` 或同为 `float64`（混用变量时不会自动提升）；若其中一个是无类型常量，则须能转换为另一个实参的浮点类型；若两个实参都是合法的无类型数值常量，则结果为无类型复数常量。复数支持四则运算与 `==`、`!=` 判等，不支持大小比较和 `%` 取余。

## 2.4 显式类型转换 {#ch2-4}

Go 不支持不同数值类型变量之间的隐式类型提升。只要赋值不满足语言规范的可赋值性条件（例如后文将介绍的具体类型赋给其实现的接口、具名复合类型与底层类型相同的未命名类型互赋），或常规算术/按位二元运算两侧的变量类型不同（移位运算 `x << n`、`x >> n` 除外，其右操作数独立要求整数类型而不必与左操作数同类型），就必须通过 `T(v)` 显式转换：

```go
var x int = 10
var y float64 = 30.2

sum := float64(x) + y
whole := x + int(y)     // 小数部分向零截断
fmt.Println(sum, whole) // 40.2 40
```

显式转换只是告诉编译器“这里由开发者承担转换后果”，并不会消除信息丢失：宽整型变量转窄整型会直接截断高位字节；浮点变量转整型会向零截去小数部分，且若浮点值超出目标整型可表示范围，转换结果依赖具体架构实现。相比之下，无类型常量赋给具体类型时会在编译期做严格的可表示性检查：

```go
var a byte = 255 // 合法
// var b byte = 256 // 编译错误：常量 256 超出 byte 表示范围
var c int = 20.0 // 合法：无类型常量 20.0 的数学值是精确整数 20
// var d int = 20.5 // 编译错误：常量含非零小数部分，无法由 int 无损表示
```

判断无类型常量能否赋给整型变量，看的是它的**数学值**能否被目标类型无损表示：`20.0` 虽带小数点，数学值仍是整数 `20`；但一旦源值已经是 `float64` 变量，哪怕里面存的就是 `20.0`，也必须显式写成 `int(v)`。

还要避开一个经典误区：不要用 `string(x)` 把整数转成十进制字符串——`string(65)` 会把整数当作 Unicode 码点生成 `"A"`，超出有效码点时则会变成替换字符 `"�"`（自 Go 1.15 起，`go vet` 的 `stringintconv` 检查会直接报告此类转换）。整数与十进制文本互转应使用标准库 `"strconv"`（如 `strconv.Itoa`）。同样，Go 不允许用 `bool(x)` 把数值、字符串或指针强转为布尔值，应直接写 `x != 0`、`s != ""` 等比较表达式。

## 2.5 无类型常量与默认类型 {#ch2-5}

声明时未写明类型的常量就是无类型常量。它不提前绑定固定的机器类型，只要满足目标类型的可表示性，就能直接赋给多种兼容类型：

```go
const value = 10
var i int = value
var f float64 = value
var b byte = value
```

无类型常量依然带有基础种类（布尔、整数、浮点数、字符、字符串、复数）。当上下文没有给出目标类型时——例如用于短变量声明 `:=` 或赋给空接口 `any`（Go 1.18+ 引入的 `interface{}` 别名）——编译器会按其种类落回默认类型：布尔值为 `bool`，整数为 `int`，浮点数为 `float64`，字符为 `rune`，字符串为 `string`，复数为 `complex128`。因此 `x := 20.0` 会推导为 `float64`，而 `var x int = 20.0` 则直接采用显式声明的 `int`。

数值常量表达式在编译期以高精度算术求值（语言规范要求整数常量至少具备 256 位精度，浮点常量具备更高阶尾数精度）。这意味着中间常量表达式可以远超任何机器整型的上限，只要最终赋给变量时的结果落在目标类型范围内即可。

一旦给常量显式加上类型，它就变成有类型常量（Typed Constant），从此受常规类型一致性约束：

```go
const typedValue int = 10
// var f float64 = typedValue // 编译错误：int 类型的常量不能隐式赋给 float64
```

因此，通用的数学系数、阈值和超时倍数通常保持无类型以保留复用弹性；只有专门用来约束某组枚举或函数参数类型时，才声明为有类型常量。

## 2.6 `var`、`:=` 与 `const` {#ch2-6}

### 2.6.1 `var` 变量声明 {#ch2-6-var}

`var` 既可用于包级作用域，也可用于函数体内，支持零值声明、显式指定类型、按初值推导类型以及分组集中声明：

```go
var count int
var limit = 10
var x, y int = 1, 2

var (
	name        = "Go"
	version int = 1
)
```

### 2.6.2 `:=` 短变量声明 {#ch2-6-short-variable-declaration}

短变量声明 `:=` 只能在函数内部（含控制结构的初始化子句）使用，要求左侧至少包含一个**当前词法块尚未声明过**的非空白新变量。若左侧同时包含当前词法块内已有的同名同类型变量（包括当前函数的形参或具名返回值），`:=` 会一并对旧变量完成重新赋值：

```go
x := 10
x, y := 20, "hello" // x 重新赋值，y 为新声明变量
```

对函数形参重赋值同样适用这一规则。下例需导入标准库 `"strings"`（其中 `strings.CutPrefix` 自 Go 1.20 起提供）：

```go
func normalize(input string) (string, bool) {
	input, changed := strings.CutPrefix(input, "-") // input 重赋值，changed 为新变量
	return input, changed
}
```

空白标识符 `_` 不算新变量；如果 `:=` 左侧没有任何新声明的非空白变量，编译器会直接报错，此时应改用普通赋值 `=`。

最容易踩坑的地方在于嵌套代码块：只要同名变量声明在**外层**块而非当前块，内层写下 `x := ...` 就会创建一个全新的局部变量，从而触发**变量隐藏**（Variable Shadowing，又称“变量遮蔽”，详见 [4.2 节](./chapter-04#ch4-2)）。典型事故是先在外层写 `var client *Client`，又在 `if` 分支里写 `client, err := newClient()`——由于右侧顺带引入了新变量 `err`，编译器不会报错，而是静默在内层新建了一个局部 `client`，导致外层 `client` 始终停留在 `nil`。

函数内部一般优先用 `:=`，但遇到以下三种意图时用 `var` 更清晰：

- **依赖零值起步**：写 `var count int`，一眼看出初值就是零值，不必写成冗余的 `count := 0`；
- **指定非默认类型**：写 `var id int32 = 20`，比 `id := int32(20)` 更直接；
- **跨分支赋值并避免变量隐藏**：先在外层用 `var client *Client`、`var err error` 声明好变量，再在分支内部统一用 `=` 赋值。

### 2.6.3 `const` 常量声明 {#ch2-6-const}

`const` 可出现在包级或函数内部，只能绑定编译期即可算出结果的布尔、数值、字符串或合法常量表达式。下例中的 `time.Second` 来自标准库 `"time"`（其底层定义为整型的纳秒常量）：

```go
const (
	readTimeout = 5 * time.Second
	serviceName = "billing"
)
```

普通函数调用返回值以及任何依赖运行时变量的表达式都不能赋给 `const`；内置函数 `len`、`cap`、`complex`、`real`、`imag` 等也只有在实参满足编译期求值条件时才能写入常量表达式（例如 `len("Go")` 是常量，而切片变量的长度 `len(s)` 不是常量）。需要成组定义递增枚举或位掩码常量时，可配合常量生成器 `iota`，相关用法将在后续自定义类型与枚举章节展开。另外，Go 的 `const` 不能用于修饰数组、切片、映射或结构体，语言层面也没有把运行期变量标记为“只读不可变”的关键字。

## 2.7 变量的使用与命名 {#ch2-7}

函数内声明的每个局部变量都必须至少被读取一次，否则无法通过编译；包级变量虽不强制要求在包内被读取，但可变的包级状态会让数据流难以追踪并带来并发竞态风险，日常设计应尽量少用。未使用的 `const` 常量在运行期不占可变状态、也没有副作用，编译器不会报错。

需要注意，编译器的“已使用检查”只看局部变量有没有出现在某处右值读取中，并不保证每一次写入的值都被消费过。例如 `x := 10; x = 20; fmt.Println(x); x = 30` 完全能通过编译，尽管 `10` 被直接覆盖、末尾的 `30` 也从未被读取——这类无效赋值需要靠 `staticcheck` 等静态分析工具进一步检出。

同理，每个源文件 `import` 的包也必须在该文件内实际用到，仅为了触发包 `init` 副作用而导入时须显式写成空白导入 `import _ "pkg"`。

虽然词法规范允许包含汉字等 Unicode 字母的标识符，但为了跨工具协作与可读性，Go 代码普遍遵循以下命名惯例：

- **统一使用驼峰命名（MixedCaps）**：多词组合写作 `requestCount`、`MaxRetries`，不用下划线分隔的蛇形命名（`request_count`）。
- **名称长短匹配作用域大小**：几行之内的循环或短块用单字母或短词（如 `i`、`k`、`v`），作用域越广（尤其是包级导出标识符），名称越要自带清晰上下文。
- **常量同样按可见性使用驼峰式**：Go 靠首字母大小写区分包外导出与包内私有，常量应写作 `MaxRetries` 或 `defaultTimeout`，不用其他语言常见的 `MAX_RETRIES`。
- **首字母缩略词（Initialisms）全大写或全小写**：像 `ID`、`URL`、`HTTP` 这类缩略词，整段保持统一大小写（导出写 `UserID`、`ServeHTTP`、`HTTPClient`，未导出写 `userID`、`httpClient`），不写成 `UserId` 或 `HttpClient`。
- **去掉类型后缀与视觉噪声**：变量名表达角色而非重复类型（用 `users` 而非 `userSlice`），同时避免易混淆的近形字符。

## 练习 {#ch2-exercises}

以下三题分别检验常量可表示性与有类型赋值、定宽整数溢出回绕，以及编译期常量与运行期浮点比较的差异。除题干另有说明外，练习 3 的代码片段位于 `main` 函数内且已导入 `"fmt"`。建议先独立推理作答，再展开核对参考答案。

### 练习 1：区分常量类型与显式转换

以下声明位于包级作用域，每次仅单独保留 `a`～`f` 中的一条与前两行 `const` 一起编译。判断哪些能通过编译；对编译失败项，在不改动等号右侧字面量或常量值的前提下写出修复方式（可加显式转换或调整左侧变量类型），并说明原因属于“常量可表示性”还是“有类型赋值类型不匹配”。

```go
const flexible = 255
const typed uint16 = 255

var a uint8 = flexible
var b uint8 = typed
var c = uint8(typed)
var d uint8 = 256
var e int = 20.0
var f int = 20.5
```

<details>
<summary>查看参考答案</summary>

`a`、`c`、`e` 可通过编译；`b`、`d`、`f` 编译失败。

- `a` 合法：`flexible` 是无类型整数常量，数值 `255` 落在 `uint8` 的可表示范围（`0`～`255`）内。
- `b` 失败（有类型赋值类型不匹配）：`typed` 已绑定具体类型 `uint16`，不能隐式赋给 `uint8`，必须像 `c` 那样做显式转换。
- `d` 失败（常量可表示性问题）：无类型常量 `256` 超出 `uint8` 上界 `255`。
- `e` 合法：无类型浮点常量 `20.0` 的数学值是精确整数 `20`，可由 `int` 无损表示。
- `f` 失败（常量可表示性问题）：无类型常量 `20.5` 带有非零小数部分，无法由整型无损表示。

保留右侧原值的修复写法：

```go
var b uint8 = uint8(typed)
var d uint16 = 256
var f float64 = 20.5
```

</details>

### 练习 2：解释定宽整数回绕并补充边界检查

不运行程序，写出以下代码的输出结果，并为“达到类型上界时保持原值不变”的需求补上自增前的边界检查。同时判断包级声明 `const u uint8 = 255 + 1` 与 `const s int8 = 127 + 1` 能否通过编译。

```go
package main

import "fmt"

func main() {
	u := uint8(255)
	s := int8(127)
	u++
	s++
	fmt.Println(u, s)
}
```

<details>
<summary>查看参考答案</summary>

输出结果为：

```text
0 -128
```

运行期变量 `u` 和 `s` 执行 `++` 时发生整数溢出，分别按模 2⁸ 与 8 位二进制补码规则静默回绕为 `0` 和 `-128`，不会触发 `panic`。而两条包级 `const` 声明在编译期求值时便已超出目标类型表示范围，编译直接失败；同理，直接写 `uint8(255) + 1` 属于有类型常量表达式溢出，也会在编译期被拦截。

把两行自增替换为如下边界保护（需导入标准库 `"math"`），即可在触达上界时保持原值，输出变为 `255 127`：

```go
if u < math.MaxUint8 {
	u++
}
if s < math.MaxInt8 {
	s++
}
```

</details>

### 练习 3：判断浮点数是否近似相等

解释以下两行比较输出为何不同，并将最后一行改写为允许绝对误差不超过 `1e-9` 的近似比较。

```go
const exact = 0.1 + 0.2
x, y := 0.1, 0.2
fmt.Println(exact == 0.3)
fmt.Println(x+y == 0.3)
```

<details>
<summary>查看参考答案</summary>

第一行输出 `true`，第二行输出 `false`。`exact` 是无类型常量表达式，在编译期以高精度算术求值，结果与常量 `0.3` 相等；而变量 `x`、`y` 在初始化时已分别舍入为 IEEE 754 `float64` 二进制近似值，运行期相加后的尾数与 `0.3` 的 `float64` 表示存在细微偏差。

引入绝对误差阈值的近似比较写法如下（需导入标准库 `"math"`）：

```go
const epsilon = 1e-9
fmt.Println(math.Abs((x+y)-0.3) <= epsilon)
```

注意误差阈值需要结合业务精度与数值量级选取：当待比较数值远离 `1.0`（例如极大或极小的科学计算数值）时，固定绝对误差不再适用，应改用相对误差或混合误差判断。

</details>

## 面试题 {#ch2-interview}

以下三题分别检验零值与 `nil` 的适用边界、逻辑短路求值顺序，以及短变量声明的新变量约束。代码片段均位于 `main` 函数内，且已导入标准库 `"fmt"`。建议先独立作答，再展开核对参考答案。

### 面试题 1：未显式初始化的变量能直接读取吗？

以下代码能否编译？若能，输出什么？能否用 `count == nil` 代替 `count == 0` 判断初始值？

```go
var count int
var ready bool
var name string
fmt.Printf("%d %t %q\n", count, ready, name)
```

<details>
<summary>查看参考答案</summary>

可以通过编译，输出 `0 false ""`。Go 变量声明后若未显式赋初值，会自动获得所属类型的确定零值，不存在未初始化垃圾值；其中 `string` 的零值为空字符串 `""`。不能写成 `count == nil`：`int` 是值类型，没有 `nil` 零值，与 `nil` 比较会直接编译失败（见 [2.1 节](#ch2-1)）。

</details>

### 面试题 2：短路求值能避免除零吗？

以下两行代码分别输出什么？若将 `&&` 或 `||` 左右两侧的子表达式互换，是否仍然安全？

```go
divisor := 0
fmt.Println(divisor != 0 && 12/divisor > 1)
fmt.Println(divisor == 0 || 12/divisor > 1)
```

<details>
<summary>查看参考答案</summary>

依次输出 `false`、`true`，两行都不会执行后面的整数除法。`&&` 在左侧为 `false` 时短路跳过右侧，`||` 在左侧为 `true` 时短路跳过右侧。一旦互换左右两侧，两行都会先求值 `12/divisor`，当场触发运行期整数除零 `panic`，因此保护条件必须写在左侧。

</details>

### 面试题 3：`:=` 左侧出现 `_` 就算有新变量吗？

以下代码位于同一词法块内，能否通过编译？第三行与第二行有何本质区别，应如何修复？

```go
x := 1
x, y := 2, 3
x, _ := 4, 5
fmt.Println(x, y)
```

<details>
<summary>查看参考答案</summary>

无法通过编译（报错 `no new variables on left side of :=`）。第二行引入了新变量 `y`，顺带对同块已有的 `x` 重赋值，满足短变量声明规则；第三行左侧的空白标识符 `_` 不计入新变量，导致 `:=` 左侧没有任何新声明的非空白变量。将第三行改为普通赋值 `x, _ = 4, 5` 即可通过编译，输出 `4 3`。

</details>
