# 第 2 章 基础类型、常量与变量

## 本章要点

Go 在基础类型系统上确立了三项核心约束：未显式初始化的变量自动获得确定零值，不同数值类型的变量之间禁止隐式转换，而字面量与未指定类型的常量通过“无类型常量”保留跨类型赋值的弹性。掌握这三项规则，才能避开定宽整数静默回绕、浮点直接判等误差、`string(int)` 转换误区以及 `:=` 变量隐藏等高频缺陷，并在 `var`、`:=`、`const` 与 `iota` 之间做出准确取舍。

> 核对日期：2026 年 11 月 17 日；核对环境为 Go 1.27.4、Linux/AMD64。

## 2.1 零值与预声明基础类型 {#ch2-1}

### 2.1.1 零值速查与零值可用原则 {#ch2-1-1}

Go 中任何已声明但未显式赋初值的变量都会自动初始化为所属类型的零值，不存在未定义垃圾内存：

| 类型类别 | 零值 |
| --- | --- |
| `bool` | `false` |
| 整数、浮点数 | `0` |
| 复数 | `0 + 0i` |
| `string` | `""` |
| 指针、切片、映射、函数、通道、接口 | `nil` |
| 数组、结构体 | 各元素或各字段对应类型的零值 |

设计自定义类型时应遵循**零值可用**（Zero-Value Useful）原则，让调用方声明变量后即可直接工作而无需强制调用构造函数。例如标准库 `"bytes"` 的 `bytes.Buffer` 与 `"sync"` 的 `sync.Mutex`，在零值状态下即可直接写入字节或加锁。

```go
var count int
var name string
var tags []string
fmt.Println(count, name == "", tags == nil) // 0 true true
```

务必牢记 `nil` 的两条适用边界：

- **`nil` 只属于上表六种引用/描述符/接口类型**：`int`、`bool`、`string` 和结构体等值类型不能赋值为 `nil`，也不能与 `nil` 比较。
- **同样为零值 `nil`，可操作边界不同**：向 `nil` [切片](./chapter-03#ch3-2)直接 `append` 完全合法，而向 `nil` [映射](./chapter-03#ch3-4)写入键值会立即触发运行期 `panic`。

### 2.1.2 布尔、整数、浮点数与复数 {#ch2-1-2}

**布尔型（`bool`）**只取 `true` 或 `false`。Go 禁止将数值 `0`、空字符串 `""` 或 `nil` 隐式当作布尔值，条件表达式结果必须为 `bool`。逻辑与 `&&` 和逻辑或 `||` 遵循**短路求值**：左操作数足以决定结果时跳过右侧求值，常用于前置下标与空指针保护，如 `i >= 0 && i < len(items) && items[i] != ""`。

**整数类型**包含定宽整数、平台相关整数与别名类型：

| 类型 | 位宽与表示范围 | 定位与选型说明 |
| --- | --- | --- |
| `int8` / `int16` / `int32` / `int64` | 8 / 16 / 32 / 64 位有符号，$-2^{n-1} \sim 2^{n-1}-1$ | 二进制协议、磁盘格式或精确位宽场景 |
| `uint8` / `uint16` / `uint32` / `uint64` | 8 / 16 / 32 / 64 位无符号，$0 \sim 2^n-1$ | 位掩码、哈希、原始字节流或协议头 |
| `int` / `uint` | 随目标架构为 32 或 64 位，两者等宽 | 业务计数、索引与长度默认首选 `int` |
| `byte` / `rune` | `uint8` / `int32` 的类型别名 | 分别强调原始字节与单个 Unicode 码点 |
| `uintptr` | 容纳指针位模式的无符号整数 | 仅用于底层转换，不可持有对象引用，见 [19.2 节](./chapter-19#ch19-2) |

常规计数与下标应统一优先使用 `int`：哪怕在 64 位平台上 `int` 与 `int64` 位宽相同，两者仍是不能直接混算的不同类型；同时切勿仅因“业务值非负”就选用 `uint`，否则 `a - b` 在 `a < b` 时会下溢回绕成极大正数。

整数运算与溢出有四条高频规则：

- **除法与取余**：整数除法向零截断（`-7 / 3 == -2`），余数符号与被除数一致（`-7 % 3 == -1`）；除数为常量 `0` 时编译报错，为运行期零值变量时触发 `panic`。
- **运行期溢出静默回绕**：变量加减乘溢出**不会** `panic`，无符号数按模 $2^n$ 回绕，有符号数按二进制补码回绕；敏感计算须在运算前检查上下界。
- **位运算符**：除 `&`、`|`、`<<`、`>>` 外，`^` 作二元运算表示异或、作一元前缀 `^x` 表示按位取反；`&^` 为位清除，将右操作数为 `1` 的对应位清零。
- **自增与自减**：`++` 和 `--` 是独立语句而非表达式，不能写 `y := x++` 或前缀 `++x`。

**浮点数与复数**：`float32` 与 `float64` 实现 IEEE 754 标准，分别提供约 6～7 位和 15～16 位十进制有效精度，默认应选 `float64`。二进制浮点数无法精确表示 `0.1`、`0.2` 等十进制小数：近似计算结果不能直接用 `==` 比较，而应结合误差阈值判断；金融金额严禁用浮点数，应改用最小货币单位整型或十进制高精度库。

在官方工具链中，编译期常量除零（如 `1.0 / 0.0`）无法通过编译；运行期非零浮点变量除以 `0.0` 得到 `±Inf`，`0.0 / 0.0` 得到 `NaN`。任何与 `NaN` 的相等比较均为 `false`（含 `x == x`），检测 `NaN` 或无穷必须使用标准库 `"math"` 的 `math.IsNaN` 与 `math.IsInf`。复数 `complex64` 和 `complex128` 通过 `complex(re, im)` 构造（实部与虚部变量须同类型），用 `real(z)`、`imag(z)` 提取分量，仅支持四则运算与 `==`、`!=` 判等，扩展函数见 `"math/cmplx"`。

### 2.1.3 字面量与字符、字符串基础 {#ch2-1-3}

数值字面量支持十进制 `42`、二进制 `0b101010`（Go 1.13+）、八进制 `0o755`（Go 1.13+，勿用旧式 `0755`）、十六进制 `0x2a`、十六进制浮点 `0x1.2p5`（Go 1.13+，须带 `p` 指数）和虚数 `1.5i`。数位分隔符 `_`（如 `1_000_000`）只能放在连续数码之间或紧跟进制前缀之后。

单引号包裹单个 Unicode 码点字面量（如 `'A'`、`'\n'`、`'中'`），默认类型为 `rune`。双引号包裹解释型字符串，解析转义序列且不可跨行；反引号包裹原始字符串，不解析转义且允许直接跨行，源码中的 `\r` 会被自动丢弃：

```go
interpreted := "line1\nline2"
raw := `line1
line2`
```

`string` 底层是**不可变的字节序列**，支持 `==`、按字节字典序比较 `<` / `>` 及 `+` 拼接，但禁止按下标修改字节（`s[0] = 'a'` 编译失败）。UTF-8 编码与字节、码点的关系详见 [3.3 节](./chapter-03#ch3-3)。

## 2.2 显式类型转换 {#ch2-2}

Go 禁止不同具体类型的变量之间隐式转换，跨类型赋值或二元运算必须显式写作 `T(v)`；移位运算 `x << n` 例外，其右操作数独立要求整型：

```go
var x int = 10
var y float64 = 30.8
sum := float64(x) + y
whole := x + int(y) // 小数向零截断，结果为 40
```

显式转换不消除精度损失：宽整型转窄整型直接截断高位字节；浮点数转整型截去小数，超出目标整型范围时结果依赖硬件架构。相比之下，无类型常量赋给变量时会在编译期按**数学值**做严格的可表示性检查：

```go
var a byte = 255 // 合法
// var b byte = 256 // 编译错误：常量 256 超出 byte 范围
var c int = 20.0 // 合法：数学值为精确整数 20
// var d int = 20.5 // 编译错误：含非零小数，无法由 int 无损表示
```

切忌用 `string(65)` 将整数转为十进制文本：它会按 Unicode 码点生成 `"A"`，超出有效码点时生成替换码点 `U+FFFD`，且会被 `go vet` 的 `stringintconv` 检查（Go 1.15+）直接拦截。整数与十进制字符串互转应调用标准库 `"strconv"` 的 `strconv.Itoa` / `strconv.Atoi`；数值转布尔值同样不支持 `bool(x)`，应直接写 `x != 0`。

## 2.3 无类型常量、`const` 与 `iota` 枚举 {#ch2-3}

### 2.3.1 无类型常量与默认类型 {#ch2-3-1}

字面量（如 `10`、`3.14`、`"go"`）属于**无类型常量**；声明 `const` 时若省略类型，常量会**沿用右侧表达式的类型**——只有当右侧本身是无类型常量表达式时，声明出的才是无类型常量；若右侧已有明确类型（例如 `const x = int32(1); const y = x` 或 `const d = 5 * time.Second`），则 `x`、`y` 均为有类型常量 `int32`，`d` 为有类型常量 `time.Duration`。无类型常量在编译期以高精度算术求值，语言规范保证整数常量至少具备 256 位精度；中间表达式可超出机器字长，只要最终结果能由目标类型表示即可直接赋给任意兼容类型。当用于 `:=` 或空接口 `any`（Go 1.18+）等缺少目标类型的上下文时，编译器按常量种类推导默认类型：

- 布尔 → `bool`，整数 → `int`，浮点数 → `float64`，字符 → `rune`，字符串 → `string`，复数 → `complex128`。

一旦常量带有具体类型（无论是显式声明 `const limit int = 10`，还是沿用了右侧有类型常量表达式），便失去跨类型直接赋值的灵活性。`const` 只能绑定编译期可求值的布尔、数值、字符串表达式，例如标准库 `"time"` 的 `5 * time.Second` 或 `len("Go")`；它不能绑定普通函数返回值、运行期变量，也不能修饰数组、切片、映射或结构体。

### 2.3.2 使用 iota 定义内部枚举 {#ch2-3-2}

Go 没有 `enum` 关键字，习惯通过“整型[定义类型](./chapter-07#ch7-1) + `const` 块 + `iota`”定义进程内枚举：

```go
type MailCategory int

const (
	Uncategorized  MailCategory = iota // 0：将零值留给“未知/未分类”默认状态
	Personal                           // 1
	Spam                               // 2
	Social                             // 3
	Advertisements                     // 4
)
```

常量生成器 `iota` 遵循两条精确规则：① 在每个 `const` 块首行重置为 `0`，块内每增加一行常量声明（无论该行是否写出 `iota`），`iota` 自动加 `1`；② 省略类型与表达式的行会原样复用上一行的表达式模板：

```go
const (
	Field1 = 0
	Field2 = 1 + iota // 1 + 1 = 2
	Field3 = 20       // 20（此行 iota 为 2）
	Field4            // 复用上一行字面量 20（此行 iota 为 3）
	Field5 = iota     // 重新引用 iota，结果为 4
)
```

使用 `iota` 须严守两条工程边界：

- **严禁用于外部持久化或协议编码**：落库状态码、配置文件或网络协议字段一旦用 `iota` 生成，后续在中间增删常量会使后方数值全部错位；外部契约编码必须显式写死字面量。
- **不阻止越界强转**：编译器允许调用方写出 `MailCategory(99)`，处理外部输入时 `switch` 仍须保留 `default` 分支；需要自动生成枚举的 `String()` 方法时，可配合 `stringer` 与 `go generate`，详见 [12.3.2 节](./chapter-12#ch12-3-2)。

## 2.4 变量声明与命名惯例 {#ch2-4}

### 2.4.1 var 与 := 的取舍 {#ch2-4-1}

`var` 可用于包级或函数内；短变量声明 `:=` 只能用于函数内部，要求左侧至少包含一个**当前词法块尚未声明过**的非空白（非 `_`）变量，并可同时对当前块已有的同名同类型变量重赋值，包含函数形参或具名返回值。下例调用标准库 `"strings"` 的 `strings.CutPrefix`（Go 1.20+）：

```go
func normalize(input string) (string, bool) {
	input, changed := strings.CutPrefix(input, "-") // input 重赋值，changed 为新变量
	return input, changed
}
```

一旦进入嵌套块（如 `if`、`for` 花括号），`:=` 不会复用外层变量，而是新建局部变量造成**变量隐藏**，详见 [4.2 节](./chapter-04#ch4-2)。函数内默认用 `:=`，遇到以下三种场景优先用 `var`：

- **以零值起步**：写 `var count int`，直接表达依赖零值，胜过 `count := 0`；
- **指定非默认类型**：写 `var id int32 = 20`，避免 `id := int32(20)` 的重复转换；
- **跨分支赋值防遮蔽**：先在外层 `var client *Client`、`var err error`，分支内统一用 `=` 赋值。

### 2.4.2 未使用检查与命名规范 {#ch2-4-2}

函数内声明的局部变量必须至少作为右值被读取一次，否则编译报错；但已使用检查不拦截被直接覆盖的无效写入，此类问题需靠 `staticcheck` 检出，详见 [12.2.1 节](./chapter-12#ch12-2-1)。未使用的 `import` 同样编译报错，仅触发包 `init` 时须写空白导入 `import _ "pkg"`；未使用的 `const` 不报错；可变的包级变量易引入数据流耦合与并发竞态，应尽量避免。

Go 社区通行以下命名规范：

- **统一驼峰命名（MixedCaps）**：凭首字母大小写控制包外导出与包内私有，常量同样写 `MaxRetries` 或 `defaultTimeout`，不用 `snake_case` 或 `MAX_RETRIES`。
- **首字母缩略词大小写一致**：`ID`、`URL`、`HTTP` 等缩略词整体全大写或全小写，写作 `UserID`、`HTTPClient`、`httpClient`、`ServeHTTP`，不写 `UserId` 或 `HttpClient`。
- **名幅匹配作用域且不带类型后缀**：几行短循环用 `i`、`v`，跨屏幕或导出标识符写清业务语义；用 `users` 而非 `userSlice`。

## 练习 {#ch2-exercises}

以下 2 道练习检验常量可表示性、显式类型转换、定宽整数回绕与 `iota` 行计数规则。除题干另有说明外，代码位于包级或 `main` 函数内且已导入 `"fmt"`。建议先独立作答，再展开核对参考答案。

### 练习 1：无类型常量可表示性与显式转换

以下声明位于包级作用域，每次仅单独保留 `a`～`f` 中的一行与前两行 `const` 一起编译。判断哪些能通过编译；对失败项说明属于“有类型不匹配”还是“常量可表示性越界”，并给出保留右侧原值的修复写法。

```go
const flexible = 255
const typed uint16 = 255

var a uint8 = flexible
var b uint8 = typed
var c = uint8(typed)
var d uint8 = 256
var e int = 20.0
var f int = 20.5
```

<details>
<summary>查看参考答案</summary>

`a`、`c`、`e` 编译通过；`b`、`d`、`f` 编译失败：

- `a`、`e` 合法：无类型常量 `255` 与数学值为整数的 `20.0` 分别可由 `uint8` 和 `int` 无损表示。
- `b` 失败（有类型不匹配）：`typed` 已绑定 `uint16`，不能隐式赋给 `uint8`，修复为 `var b uint8 = uint8(typed)`。
- `d` 失败（常量可表示性越界）：`256` 超出 `uint8` 上限 `255`，修复为 `var d uint16 = 256`。
- `f` 失败（常量可表示性越界）：`20.5` 含非零小数，修复为 `var f float64 = 20.5`。

</details>

### 练习 2：定宽整数回绕与 iota 枚举边界

不运行程序，写出以下代码的完整输出结果，并判断若将 `u++` 改为包级常量声明 `const overflow uint8 = 255 + 1` 能否通过编译。

```go
const (
	FlagNone = 0
	FlagRead = 1 << iota
	FlagWrite
	FlagAll = 7
	FlagCopy
	FlagNext = iota
)

func main() {
	u, s := uint8(255), int8(127)
	u++
	s++
	fmt.Println(u, s)
	fmt.Println(FlagNone, FlagRead, FlagWrite, FlagAll, FlagCopy, FlagNext)
}
```

<details>
<summary>查看参考答案</summary>

输出结果为：

```text
0 -128
0 2 4 7 7 5
```

- **定宽整数回绕**：运行期变量 `u`（`uint8`）和 `s`（`int8`）自增溢出时不会 `panic`，分别按模 $2^8$ 和 8 位补码静默回绕为 `0` 与 `-128`；而 `const overflow uint8 = 255 + 1` 属于编译期常量求值，超出 `uint8` 表示范围会直接编译报错。
- **`iota` 逐行递增与模板复用**：`FlagNone` 处 `iota=0`；`FlagRead` 处 `iota=1` 得 `1<<1 = 2`；`FlagWrite` 复用 `1<<iota` 且 `iota=2` 得 `4`；`FlagAll` 显式取 `7`（`iota=3`）；`FlagCopy` 复用字面量 `7`（`iota=4`）；`FlagNext` 重新引用 `iota` 得 `5`。

</details>

## 面试题 {#ch2-interview}

以下 3 道面试题聚焦短路求值与除零边界、`:=` 重赋值规则及 IEEE 754 浮点判等陷阱。代码上下文同[练习部分](#ch2-exercises)。建议先独立作答，再展开核对参考答案。

### 面试题 1：短路求值能否阻止除零？常量除零又如何？

写出以下两行代码的输出。若互换 `&&` 两侧表达式，或将右侧改为常量表达式 `12 / 0 > 1`，结果分别是什么？

```go
divisor := 0
fmt.Println(divisor != 0 && 12/divisor > 1)
fmt.Println(divisor == 0 || 12/divisor > 1)
```

<details>
<summary>查看参考答案</summary>

原代码依次输出 `false`、`true`：`&&` 在左侧为 `false`、`||` 在左侧为 `true` 时均短路跳过右侧运行期除法。若互换两侧，会先求值变量除零 `12/divisor`，当场触发运行期 `panic`；若写成常量除零 `12 / 0 > 1`，即使位于短路右侧，编译器仍会在**编译期**直接报错拒绝。

</details>

### 面试题 2：`:=` 左侧包含 `_` 就算引入了新变量吗？

同一词法块内的以下代码能否通过编译？第三行与第二行有何区别，如何修复？

```go
x := 1
x, y := 2, 3
x, _ := 4, 5
fmt.Println(x, y)
```

<details>
<summary>查看参考答案</summary>

无法通过编译，报错信息为 `no new variables on left side of :=`。第二行声明了新变量 `y`，可合法对同块已有的 `x` 重赋值；第三行的空白标识符 `_` 不计入新变量，导致左侧无任何新声明变量。将第三行改为普通赋值 `x, _ = 4, 5` 即可编译通过并输出 `4 3`。

</details>

### 面试题 3：为什么不能直接用 `==` 判等浮点运算结果或检测 `NaN`？

<details>
<summary>查看参考答案</summary>

原因有二：① `float64` 采用二进制浮点表示，`0.1`、`0.2` 等十进制小数存入变量时已发生二进制舍入，运行期 `x, y := 0.1, 0.2` 计算 `x+y == 0.3` 会因尾数舍入偏差返回 `false`，而编译期无类型常量 `0.1 + 0.2 == 0.3` 用高精度求值才为 `true`；近似比较须借助误差阈值如 `math.Abs((x+y)-0.3) <= 1e-9`。② 按 IEEE 754 规范，`NaN` 与任何值（含自身 `x == x`）比较都返回 `false`，检测 `NaN` 必须调用 `math.IsNaN(x)`。

</details>
