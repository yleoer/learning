# 第 2 章 基础类型和变量声明

## 本章要点

本章阐述 Go 的零值机制、预声明基础类型、常量类型系统与变量声明语义。Go 类型系统要求显式类型转换，不支持隐式数值类型转换，也不将非布尔值隐式视为布尔条件。掌握零值语义、无类型常量的可表示性以及显式类型转换规则，是编写类型安全代码的基础，也是在 `var`、`:=` 与 `const` 之间合理取舍的前提。

> 核对日期：2026 年 10 月 15 日；核对环境为 Go 1.27.2、Windows/AMD64。

## 2.1 零值：未初始化也有确定的值 {#ch2-1}

未显式指定初始值的变量，在声明后自动获得所属类型的零值：

| 类型 | 零值 |
| --- | --- |
| `bool` | `false` |
| 整数、浮点数 | `0` |
| 复数 | `0 + 0i` |
| `string` | `""` |
| 指针、切片、映射、函数、通道、接口 | `nil` |
| 数组、结构体 | 各元素或字段对应类型的零值 |

零值是语言规范提供的确定性保证。类型设计应遵循“零值可用”（Zero-Value Useful）原则，使调用方声明变量后即可直接操作，无需依赖额外的构造函数。例如标准库的 `bytes.Buffer` 与 `sync.Mutex` 在零值状态下即可直接读写或加锁。

```go
var count int
var ready bool
var name string
var tags []string

fmt.Println(count, ready, name == "", tags == nil)
// 0 false true true
```

`nil` 并非适用于所有类型的通用值，仅可表示指针、切片、映射、函数、通道和接口的零值；整型、布尔型与结构体等不存在 `nil` 零值。此外，零值同为 `nil` 的复合类型在运行时的读写语义亦不相同：向零值[切片](./chapter-03#ch3-2)追加元素（`append`）完全合法，而向零值[映射](./chapter-03#ch3-4)直接写入键值则会触发运行时 `panic`。

## 2.2 字面量 {#ch2-2}
字面量（Literal）是源码中直接表示固定值的语法形式。本节讨论的整数、浮点数、虚数、字符和字符串字面量均为无类型常量（Untyped Constant），在参与赋值或运算时才根据上下文确定具体类型；[第 3 章的数组、切片等复合字面量](./chapter-03#ch3-1)则具有明确的类型。

### 2.2.1 整数

```go
42          // 十进制
0b101010    // 二进制
0o755       // 八进制
0x2a        // 十六进制
1_000_000   // 下划线仅用于分隔数位以提升可读性
```

旧式前导零（如 `010`）同样表示八进制，但极易与十进制混淆，代码应统一使用语义明确的 `0o` 前缀。下划线 `_` 只能紧跟在进制前缀（`0b`、`0o`、`0x`）之后，或位于两个连续数码（含十六进制数码 `a`～`f`）之间；不可位于字面量首尾或连续出现。由于小数点与指数符号（`e`、`p`）并非进制前缀，`1_.0`、`1._0` 和 `1e_3` 均属语法错误。

### 2.2.2 浮点数和复数

```go
3.14
6.03e23
0x1.2p5       // 十六进制浮点字面量
1.5i           // 虚数字面量
```

`0x1.2p5` 表示十六进制尾数 `1.2`（即十进制 `1.125`）乘以 2⁵，等价于十进制 `36`；其中 `p` 指定以 2 为底的指数。浮点字面量作为无类型常量时不受 `float64` 精度限制，仅在赋予具体浮点变量时才按目标精度舍入。虚数字面量可与实数构成复数表达式，如 `2 + 1.5i`。

### 2.2.3 字符与字符串

字符（rune）字面量以单引号包裹，表示单个 Unicode 码点（Code Point），默认类型为 `rune`：

```go
'A'
'中'
'\n'
'\u4E2D'
```

解释型字符串使用双引号，支持转义序列且不可跨行；原始字符串使用反引号，不解析转义序列并支持跨行（不可包含反引号，源码中的回车符 `\r` 会在编译期自动剔除）：

```go
interpreted := "line1\nline2"
raw := `line1
line2`
```

`string` 的零值为空字符串 `""`。字符串支持 `==`、`!=` 相等性比较，支持 `<`、`<=`、`>`、`>=` 按底层字节序列进行字典序比较，支持 `+` 拼接。字符串底层为不可变字节序列：可以对字符串变量整体重新赋值，但不能通过索引修改单字节（如 `s[i] = 'a'` 非法）。关于字符串、UTF-8 编码与 `byte`、`rune` 的映射关系，详见 [3.3 节](./chapter-03#ch3-3)。

## 2.3 布尔与数值类型 {#ch2-3}

### 2.3.1 布尔值

`bool` 仅取值 `true` 或 `false`，零值为 `false`。Go 不会将数值、字符串、指针或集合隐式转换为布尔值，条件表达式的结果必须为 `bool` 类型。

```go
ready := true
hasItems := count > 0
canStart := ready && hasItems
shouldWait := !ready || !hasItems
```

`!` 表示逻辑非，`&&` 表示逻辑与，`||` 表示逻辑或。`&&` 与 `||` 遵循短路求值（Short-Circuit Evaluation）规则：当左操作数足以决定整体结果时，右操作数不予执行。工程中常利用该特性前置边界校验，例如 `i >= 0 && i < len(items) && items[i] != ""`。分支与条件控制详见 [4.3 节](./chapter-04#ch4-3)。

### 2.3.2 整数

Go 预声明了定宽有符号与无符号整数类型：

| 类型 | 位宽 | 取值范围 |
| --- | ---: | --- |
| `int8` | 8 | -2⁷～2⁷-1 |
| `int16` | 16 | -2¹⁵～2¹⁵-1 |
| `int32` | 32 | -2³¹～2³¹-1 |
| `int64` | 64 | -2⁶³～2⁶³-1 |
| `uint8` | 8 | 0～2⁸-1 |
| `uint16` | 16 | 0～2¹⁶-1 |
| `uint32` | 32 | 0～2³²-1 |
| `uint64` | 64 | 0～2⁶⁴-1 |

此外还提供以下整型：

- `byte`：`uint8` 的类型别名（Alias），用于表示原始字节。
- `rune`：`int32` 的类型别名，用于表示 Unicode 码点。
- `int` 与 `uint`：平台相关位宽（32 位或 64 位，二者位宽一致）。
- `uintptr`：足以保存指针位模式的无符号整数，仅用于底层内存与跨语言互操作，不可作为常规整数使用。

在网络协议、文件格式或二进制内存布局等对位宽有严格约束的场景中，应选用 `int32`、`uint64` 等定宽类型；通用业务逻辑、索引、计数和长度应优先使用 `int`。即便在特定架构上位宽相同，`int`、`int32` 与 `int64` 在类型系统中仍属不同类型。此外，即使业务数值恒为非负，也应优先使用 `int` 而非 `uint`：无符号整数在减法运算（如 `a - b` 且 `a` 小于 `b`）或递减循环中极易因下溢回绕为巨大正数，引发隐蔽的越界或死循环；标准库 `len`、`cap` 返回 `int` 正是出于这一考量。

整数支持 `+`、`-`、`*`、`/`、`%` 算术运算、比较运算，以及 `&`（按位与）、`|`（按位或）、`^`、`&^`（位清除，将右操作数为 1 的对应位清零）、`<<`（左移）、`>>`（右移）等位运算。其中 `^` 作二元运算符时表示按位异或，作一元前缀运算符（`^x`）时表示按位取反（对应 C 系语言的 `~x`）。上述二元算术和位运算均支持 `+=`、`&^=` 等复合赋值形式。`++` 与 `--` 属于语句而非表达式，不能写成 `y := x++`。

整数除法向零截断（如 `-7 / 3 == -2`），取余运算满足恒等式 `(a / b) * b + a % b == a`（故 `-7 % 3 == -1`）。除数为零常量时直接触发编译错误；除数为运行时零值变量时触发 `panic`。运行时整数变量运算溢出不会自动触发 `panic`：无符号整数按模 2ⁿ 回绕，有符号整数按对应位宽的二进制补码规则回绕。不允许溢出的业务场景需在运算前显式校验边界。

### 2.3.3 浮点数

`float32` 和 `float64` 分别遵循 IEEE 754 标准的 32 位和 64 位二进制浮点规范，约提供 6～7 位和 15～16 位十进制有效数字精度。除外部格式约束或经性能剖析证实存在内存瓶颈外，工程中应优先使用 `float64`。

二进制浮点数可精确表示 `0.5` 等分母为 2 的幂的十进制小数，但无法精确表示 `0.1` 等值。运算符 `==` 比较浮点值本身并遵循 IEEE 754 规则，不具备误差容忍能力；近似计算应根据数值量级选用绝对误差、相对误差或二者结合。金融金额等要求精确十进制语义的场景，应采用以最小货币单位计数的整型或专用十进制运算库。

在官方 Go 工具链实现中，有限非零浮点变量除以零得到正负无穷（`±Inf`），零除以零得到非数（`NaN`）。根据 IEEE 754 规范，任何涉及 `NaN` 的相等性比较均返回 `false`（包括 `x == x`），因此判断 NaN 必须使用 `math.IsNaN`；判断无穷可使用 `math.IsInf`，不能用 `==` 判断 NaN。语言规范将运行时浮点除零是否触发 `panic` 定义为实现相关行为。若整个除法表达式为编译期常量表达式（如 `1.0 / 0.0`），编译器将直接报错；而 `x := 1.0` 后的 `x / 0.0` 属于运行时变量求值，编译期予以放行。

### 2.3.4 复数

```go
z := complex(2.5, 3.1) // 默认推导为 complex128
fmt.Println(real(z), imag(z))
```

`complex64` 的实部和虚部为 `float32`，`complex128` 的实部和虚部为 `float64`。复数运算继承 IEEE 754 浮点数的近似特性，高阶复数函数由标准库 `math/cmplx` 提供。

内置函数 `complex` 的两个有类型参数须具有相同的浮点类型（`float32` 与 `float64` 变量混用不会自动提升）；若其一为无类型常量，则须能转换为另一参数的类型；若二者均为合法的无类型数值常量，则结果为无类型复数常量。复数支持四则运算及 `==`、`!=` 比较，不支持大小比较或 `%` 运算。

## 2.4 显式类型转换 {#ch2-4}

Go 禁止不同类型的变量之间发生隐式类型提升。不同数值类型进行赋值或混合运算时，必须通过 `T(v)` 显式转换：

```go
var x int = 10
var y float64 = 30.2

sum := float64(x) + y
whole := x + int(y) // 小数部分向零截断
fmt.Println(sum, whole) // 40.2 40
```

显式转换可能伴随信息丢失：宽整型变量转为窄整型时会直接截去高位；浮点变量转为整型时会向零截去小数部分，若浮点值超出目标整型范围，结果依赖具体实现。无类型常量则在编译期校验目标类型能否精确表示该值：

```go
var a byte = 255  // 合法
// var b byte = 256 // 编译错误：常量 256 溢出 byte
var c int = 20.0  // 合法：无类型常量 20.0 表示精确整数 20
// var d int = 20.5 // 编译错误：常量包含非零小数部分，无法由 int 表示
```

无类型常量能否赋给整型变量，取决于其数学值能否由目标类型无损表示。`20.0` 虽带小数点，但仍表示整数 `20`；若源值已是 `float64` 类型的变量，则即便值为 `20.0` 也必须显式转换。

注意不要使用 `string(x)` 将整型转换为十进制文本——该语法会将整数按 Unicode 码点解释为单字符字符串（自 Go 1.15 起，`go vet` 的 `stringintconv` 检查会报告这一误用），整数与字符串的文本互转应使用 `strconv` 标准库。同理，Go 不支持将数值、字符串或指针强制转换为 `bool`，应使用 `x != 0` 或 `s != ""` 等显式比较表达式。

## 2.5 无类型常量与默认类型 {#ch2-5}

未显式指定类型的常量属于无类型常量。无类型常量不绑定固定的机器类型，在满足目标类型可表示性的前提下可直接赋给不同类型：

```go
const value = 10
var i int = value
var f float64 = value
var b byte = value
```

无类型常量仍受限于其基础种类（布尔、整数、浮点数、字符、字符串、复数）。当上下文未指定具体类型（如短变量声明 `:=` 或赋给 `any` 接口）时，编译器按默认类型完成推导：布尔值为 `bool`，整数为 `int`，浮点数为 `float64`，字符为 `rune`，字符串为 `string`，复数为 `complex128`。例如 `x := 20.0` 推导为 `float64`，而 `var x int = 20.0` 则采用显式指定的 `int`。

数值常量在编译期以高精度算术求值（语言规范要求编译器至少支持 256 位整数精度与高阶浮点精度）。无类型整数常量在编译期可超出任意机器整型的上限，但一旦赋予具体变量，则必须落在目标类型的表示范围内。

有类型常量（Typed Constant）严格遵循常规类型检查规则：

```go
const typedValue int = 10
// var f float64 = typedValue // 编译错误：不能将 int 类型的常量隐式赋给 float64
```

通用数学与配置常量通常保持无类型以获得最大调用灵活性；仅在需要通过 API 强制约束类型边界时，才声明为有类型常量。

## 2.6 `var`、`:=` 与 `const` {#ch2-6}

### 2.6.1 `var` 变量声明 {#ch2-6-var}

`var` 可用于包级作用域或函数内部，支持显式指定类型、依赖零值初始化、类型推导以及成组声明：

```go
var count int
var limit = 10
var x, y int = 1, 2

var (
	name    = "Go"
	version int = 1
)
```

### 2.6.2 `:=` 短变量声明 {#ch2-6-short-variable-declaration}

短变量声明 `:=` 仅限在函数内部使用，左侧至少须包含一个当前词法块尚未声明的新非空白变量。对于同一词法块内已声明的变量（含当前函数的形参），若类型一致，可通过包含新变量的短声明语句完成重赋值：

```go
x := 10
x, y := 20, "hello" // x 重新赋值，y 为新声明变量
```

在函数体中，短声明同样可对函数形参重赋值。下例需导入标准库 `strings`（`strings.CutPrefix` 要求 Go 1.20 及以上版本）：

```go
func normalize(input string) (string, bool) {
	input, changed := strings.CutPrefix(input, "-") // input 为形参重赋值，changed 为新变量
	return input, changed
}
```

空白标识符 `_` 不计入新变量；若左侧无新变量，仅对已有变量赋新值时必须使用 `=`。

若同名变量仅声明于外层代码块，内层块中的 `x := ...` 将创建全新的局部变量并遮蔽（Shadow）外层变量（详见 [4.2 节](./chapter-04#ch4-2)）。工程中典型的遮蔽陷阱是在外层声明 `var client *Client`，随后在 `if` 或 `for` 块内编写 `client, err := newClient()`：由于引入了新变量 `err`，内层会静默创建局部 `client`，导致外层 `client` 始终停留在零值 `nil`。

函数内部通常优先使用 `:=`。以下场景使用 `var` 更能准确表达工程意图：

- 明确依赖零值初始化：`var count int`。
- 指定异于字面量默认类型的目标类型：`var id int32 = 20`。
- 跨分支赋值或规避作用域遮蔽：先在外层显式声明变量（如 `var err error`），再于内层使用 `=` 赋值。

### 2.6.3 `const` 常量声明 {#ch2-6-const}

`const` 可用于包级或函数内部，仅能绑定编译期可求值的布尔、数值或字符串值及合法的常量表达式。下例中的 `time.Second` 需导入标准库 `time`：

```go
const (
	readTimeout = 5 * time.Second
	serviceName = "billing"
)
```

常量可由常量表达式计算得出，但常规函数调用结果及依赖运行时变量的表达式均非常量。`len`、`cap`、`complex` 等内置函数仅在参数满足编译期求值条件时才能用于常量表达式（例如 `len("Go")` 为常量，而切片变量的长度 `len(s)` 不是常量）。成组声明递增或位掩码常量时，可结合[第 7 章介绍的常量生成器 `iota`](./chapter-07#ch7-3) 使用。Go 不提供将运行期变量声明为只读的通用语法，也不支持用 `const` 保存数组、切片、映射或结构体。

## 2.7 变量的使用与命名 {#ch2-7}

函数内声明的局部变量必须至少被读取一次，否则触发编译错误；包级变量允许未被引用，但可变包级状态会增加数据流分析与并发维护成本，应严格受控。未使用的常量无运行时副作用，编译器不予报错。

编译器的局部变量使用检查并不保证每次赋值都被读取。例如 `x := 10; x = 20; fmt.Println(x); x = 30` 可正常编译，尽管初始值 `10` 与末尾的 `30` 均未被读取（此类无效赋值需借助 `staticcheck` 等静态分析工具检出）。

另一项强制规则是：源码文件导入的包必须在该文件内实际使用，否则须显式采用空白导入（`import _ "pkg"`）。

词法规范允许使用 Unicode 标识符，但工程代码应遵循统一的命名惯例以保障可读性：

- **采用驼峰式命名（MixedCaps）** ：多词标识符写作 `requestCount`、`MaxRetries`，不使用蛇形命名（`request_count`）。
- **名称长度与作用域范围匹配**：小作用域使用短名（如循环索引 `i`、键值 `k`/`v`）；包级标识符应具备清晰的描述性语义。
- **常量同样采用驼峰式**：首字母大小写承担包外可见性语义（大写导出，小写包内私有），不使用 `MAX_SIZE` 形式的全大写下划线命名。
- **首字母缩略词（Initialisms）保持大小写一致**：如 `ID`、`URL`、`HTTP` 在标识符中应全大写或全小写（导出写作 `UserID`、`ServeHTTP`、`HTTPClient`，未导出写作 `userID`、`httpClient`），避免写作 `UserId` 或 `HttpClient`。
- **避免冗余与视觉混淆**：避免将类型名重复嵌入变量名（如用 `users` 而非 `userSlice`），避免无意义下划线及易混淆的相似 Unicode 码点。

## 练习 {#ch2-exercises}

以下三题分别检验常量可表示性、定宽整数边界回绕与浮点近似比较。建议先独立作答，再展开参考答案。

### 练习 1：区分常量类型与显式转换

以下声明位于包级作用域，每次仅单独考察 `a`～`f` 中的一条（保留前两条 `const` 声明）。判断其能否通过编译；对编译失败项，在不改变右侧字面量或常量值的前提下给出修复方案（可做显式转换或调整变量类型），并说明原因属于常量可表示性问题还是有类型赋值问题。

```go
const flexible = 255
const typed uint16 = 255

var a uint8 = flexible
var b uint8 = typed
var c = uint8(typed)
var d uint8 = 256
var e int = 20.0
var f int = 20.5
```

<details>
<summary>查看参考答案</summary>

`a`、`c`、`e` 可通过编译；`b`、`d`、`f` 编译失败。

- `a` 合法：`flexible` 为无类型整数常量，其值 `255` 落在 `uint8` 的可表示范围（0～255）内。
- `b` 失败（有类型赋值问题）：`typed` 已具明确类型 `uint16`，不能隐式赋给 `uint8`，需如 `c` 所示显式转换。
- `d` 失败（常量可表示性问题）：无类型常量 `256` 超出 `uint8` 上界。
- `e` 合法：无类型浮点常量 `20.0` 的数学值为精确整数 `20`，可由 `int` 表示。
- `f` 失败（常量可表示性问题）：无类型常量 `20.5` 含非零小数部分，无法由整型表示。

保留右侧数值的修复方案：

```go
var b uint8 = uint8(typed)
var d uint16 = 256
var f float64 = 20.5
```

</details>

### 练习 2：解释定宽整数回绕并补充边界检查

不运行程序，写出以下代码的输出结果，并为“达到类型上界时保持原值”的场景补充自增前的边界检查。同时判断包级声明 `const u uint8 = 255 + 1` 与 `const s int8 = 127 + 1` 能否通过编译。

```go
package main

import "fmt"

func main() {
	u := uint8(255)
	s := int8(127)
	u++
	s++
	fmt.Println(u, s)
}
```

<details>
<summary>查看参考答案</summary>

输出结果为：

```text
0 -128
```

运行时变量 `u` 和 `s` 执行 `++` 时发生整数溢出，分别按模 2⁸ 和 8 位补码规则回绕为 `0` 和 `-128`，不会触发 `panic`。而两条 `const` 声明在编译期求值时即超出目标类型表示范围，无法通过编译。同理，直接编写表达式 `uint8(255) + 1` 属于有类型常量运算，同样会在编译期因溢出被拒绝。

将两条 `++` 语句替换为以下边界检查代码（需导入标准库 `math`），即可在达到上界时保留原值，输出变为 `255 127`：

```go
if u < math.MaxUint8 {
	u++
}
if s < math.MaxInt8 {
	s++
}
```

</details>

### 练习 3：判断浮点数是否近似相等

解释以下两行比较输出为何不同，并将最后一行改写为允许绝对误差阈值为 1e-9 的近似比较。

```go
const exact = 0.1 + 0.2
x, y := 0.1, 0.2
fmt.Println(exact == 0.3)
fmt.Println(x+y == 0.3)
```

<details>
<summary>查看参考答案</summary>

第一行输出 `true`，第二行输出 `false`。`exact` 为无类型常量表达式，在编译期以高精度算术求值，与常量 `0.3` 完全相等；而变量 `x` 和 `y` 在初始化时已分别按 IEEE 754 `float64` 精度舍入，二者运行时相加的二进制结果与 `0.3` 的 `float64` 表示存在尾数差异。

引入绝对误差阈值的近似比较写法如下（需导入标准库 `math`）：

```go
const epsilon = 1e-9
fmt.Println(math.Abs((x+y)-0.3) <= epsilon)
```

注：误差阈值应根据业务精度要求与数值量级选取；若待比较数值远离 1.0（如极大或极小的科学计算数值），固定绝对误差将失效，需改用相对误差判定。

</details>

## 面试题 {#ch2-interview}

以下三题分别考察零值语义、短路求值与短变量声明规则。

### 面试题 1：未显式初始化的变量能直接读取吗？

以下代码能否编译？若能，输出什么？能否用 `count == nil` 代替 `count == 0` 判断初始值？

```go
var count int
var ready bool
var name string
fmt.Printf("%d %t %q\n", count, ready, name)
```

<details>
<summary>查看参考答案</summary>

可以通过编译，输出 `0 false ""`。Go 变量声明后若无显式初始值，会自动赋予所属类型的确定零值，不存在未定义内存状态；`string` 的零值为空字符串 `""`。`count == nil` 无法通过编译，因为 `int` 属于值类型，不支持与 `nil` 比较（详见[各类型的零值](#ch2-1)）。

</details>

### 面试题 2：短路求值能避免除零吗？

以下两行代码分别输出什么？若将 `&&` 或 `||` 左右两侧的表达式互换，是否仍然安全？

```go
divisor := 0
fmt.Println(divisor != 0 && 12/divisor > 1)
fmt.Println(divisor == 0 || 12/divisor > 1)
```

<details>
<summary>查看参考答案</summary>

依次输出 `false`、`true`，两行均不会执行整数除法。`&&` 在左操作数为 `false` 时短路跳过右侧，`||` 在左操作数为 `true` 时短路跳过右侧。若将两侧表达式互换，两个场景均会优先求值 `12/divisor`，直接触发运行时整数除零 `panic`；因此前置保护条件必须位于左侧。

</details>

### 面试题 3：`:=` 左侧出现 `_` 就算有新变量吗？

以下代码能否通过编译？第三条语句与第二条语句有何本质区别，应如何修正？（所有语句均位于同一词法块内）

```go
x := 1
x, y := 2, 3
x, _ := 4, 5
fmt.Println(x, y)
```

<details>
<summary>查看参考答案</summary>

无法通过编译。第二条语句引入了新变量 `y`，同时对已声明的 `x` 重赋值，符合短声明规则；第三条语句左侧的空白标识符 `_` 不计入新变量，导致 `:=` 左侧没有任何新声明的非空白变量。将第三条语句改为赋值语句 `x, _ = 4, 5` 即可通过编译，输出 `4 3`。

</details>
