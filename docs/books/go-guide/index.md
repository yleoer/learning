# 前言

Go 常被形容为一门“无聊”的语言：语法不追求炫技，特性数量也刻意保持克制。它没有继承、函数重载、运算符重载、模式匹配、命名参数和异常等许多常见机制。但“无聊”并不等于平庸，恰恰意味着团队可以把注意力留给问题本身，让代码更容易阅读、部署和长期维护。

真正学会 Go，也不只是把其他语言的写法翻译成 Go 语法。写出能运行的代码只是起点；理解零值、组合、接口、显式错误、并发原语以及工具链如何协同，才能写出符合 Go 惯例的程序。这份指南的目标，正是把“会写”推进到“写得像 Go”。

## 为什么需要新版学习指南

Go 的核心语言依旧精简，生态却一直演进。泛型逐渐进入标准库，工作区、模糊测试、结构化日志和漏洞扫描等能力也成为现代 Go 工程的一部分。与此同时，Go 通过模块中的语言版本、工具链选择和 `GODEBUG` 等机制，在保持兼容性的前提下修正长期存在的设计问题。

因此，本指南不会把书中的版本号和命令原样冻结下来。章节结构以《Go语言学习指南：惯例模式与编程实践（原书第 2 版）》为主线，具体行为则结合当前 Go 官方文档核对；遇到已经变化的工具或惯例，会明确给出现代写法。

## 适合谁阅读

本指南主要面向已经接触过至少一门编程语言、正在把 Go 作为下一门语言学习的开发者。读者不必写过 Go，但最好具备以下基础：

- 会使用终端、编辑器和 Git 等开发工具；
- 理解变量、函数、抽象和并发等基本概念；
- 对 HTTP 有初步认识，以便理解后续的服务端示例。

已有 Go 经验的读者也可以把它当作惯例与现代工具链的复习材料。基础章节里看似熟悉的细节值得认真阅读：Go 与其他语言的差异常常就藏在变量作用域、值语义、错误处理和接口边界之中。

## 如何使用本指南

建议按左侧章节顺序阅读。每章正文解释概念、规则、示例和边界；练习用于独立推理、阅读或修改代码，面试题用于直接检查关键规则和易错点。先自行作答，再展开答案核对结果与原因；运行代码可以作为完成后的可选验证。

阅读代码时，本指南采用以下约定：

- `等宽字体` 表示命令、文件名、标识符、类型或环境变量；
- 代码块中的 `$` 仅表示命令行提示符，不需要输入；
- `<module-path>` 这样的占位符需要替换为你自己的值；
- 标有“核对日期”的版本信息可能随 Go 发布而变化，应以链接的官方页面为准。

各章引用块记录实际使用的核对环境，目前主要在 Windows/AMD64 上验证。为便于跨平台阅读，通用命令通常使用带 `$` 提示符的 Unix shell 写法；Windows 的命令或行为存在差异时，会另外给出 PowerShell 写法或平台说明。
